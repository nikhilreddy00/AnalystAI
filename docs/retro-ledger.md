# Retro ledger (Domains 1–6, PRs #1–#3)

One row per audit, gate, browser or retro finding, so recurrences per class can be counted. Built 2026-11-09 from `docs/baselines/phase5_7_*.md`, the two research docs, PR #1–#3, `CODING_STANDARDS.md` and the domain-depth lessons. D1/D2 notes give only counts per audit pass, so their rows come from the post-domain audit, the gate causes, carry bullets and known limits.
- **Add a row:** next id for the domain (`D7-01`, `PR4-01`); one class; `enforced-by` names the check. A finding that comes back is not a new row: add the domain to its row and raise `recurrences`.
- **Open:** a fix that starts "Open" is not fixed; its `enforced-by` is an xfail-strict test pinning the bug, which fails the suite (XPASS) the day the bug is fixed, so the row is updated then.
- **Rule:** a finding closes only with a check (test, hook, type, property, cap). Prose-only (a lesson, CODING_STANDARDS, ROADMAP text, a brief) = `unenforced`. `recurrences` = later domains/PRs where the same finding came back after this row's fix. `tests/test_retro_ledger.py` checks the format, the paths and the summary.
- **Bug classes** (PR #1): C1 rows a term counts · C2 window / partial month · C3 segment bridge · C4 level repair · C5 never a confident 0 or unknown · C6 words route meaning (glossary unit, question or header words) · C7 meaning or scale guessed from values · C8 a regex judges prose (benchmark, causal) · C9 domain words in shared Python · C0 one-off, fits no recurring class.
- **Process themes** (`docs/research/2026-11-06-recurring-retro-findings.md` §2): A fix judged on its own example · B check fires late · C process step skipped · D CI/push time · E steering files grow · F eval cost estimates · G tooling gaps.
- Plan v2 class 1 (which rows a number reads) → C1.
- Plan v2 class 2 (sandbox code a second copy of a rule) → the class of the rule copied: C1 for rows, C2 for a window.
- Plan v2 class 3 (exact vocabulary, a generic path that guesses) → C6 for header/question words; C5 when the generic path guesses instead of refusing.
- Plan v2 class 4 (retail as the base vocabulary) → C9.
- Plan v2 class 5 (output depends on the machine) → C0 (one row, D1-28).
