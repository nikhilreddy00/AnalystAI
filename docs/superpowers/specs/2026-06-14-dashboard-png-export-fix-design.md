# Dashboard PNG Export Fix — Design

**Date:** 2026-06-14
**Gap:** 3 (PNG Export Fix)
**Status:** Spec approved

---

## Problem

The dashboard "PNG" button (full-dashboard export, [AutoDashboard.tsx:246](frontend/src/components/AutoDashboard.tsx#L246)) captures more than the visual analytics layer. Specifically, the current snapshot region (`sectionRef`) includes:

1. The **FilterSidebar** — a UI affordance, not a visual analytic.
2. The "**Showing X of Y records**" indicator — a UI affordance.
3. The cross-filter chip row is uniformly **excluded** even when filters are active, leaving the PNG unable to communicate that filtering was applied.

The user's mental model is "Power BI export": only KPI cards + charts (+ a filter-applied indicator banner if relevant), plus a small dataset/date footer. Nothing else.

The user's original spec also described capturing dataset briefing, schema/quality tables, analysis report text, and the principal-analyst review — but those panels live in `ChatInterface.tsx`, not the dashboard (commit `72cfe7a` removed report text from the dashboard). The actual scope of this gap is narrower than the original framing.

## Goals

- The full-dashboard PNG contains ONLY: (optional) filter-applied chip row, KPI row, chart grid, footer.
- The PNG indicates whether filters are active by showing the chip labels (without interactive X/Reset chrome).
- A small footer line at the bottom: `<dataset_name> · Generated by AnalystAI · <YYYY-MM-DD>`.
- The downloaded file uses a dataset-aware name: `dashboard_<dataset_slug>_<date>.png`.
- Per-chart PNG export is **unchanged** (no footer, current filename = chart title slug).
- The `html-to-image` library is preserved (Tailwind v4 / shadcn use `oklch()` color functions that html2canvas cannot parse — this is a deliberate, load-bearing choice).

## Non-goals

- Adding report panels back to the dashboard. (The dashboard stays visuals-only.)
- Changing the chat-page export — chat has no PNG export today.
- Migrating off `html-to-image`.
- Changing how per-chart PNG works.
- Adding a new "Analysis details" collapsible section to the dashboard.

## Design

### Snapshot region restructure

**Current shape** of the relevant block in [AutoDashboard.tsx](frontend/src/components/AutoDashboard.tsx):

```
<section>
  <header data-html2canvas-ignore>...buttons...</header>
  <div ref={sectionRef}>              ← snapshot region
    <div data-html2canvas-ignore>     ← cross-filter chip row (always ignored)
      ...chips, X buttons, Reset...
    </div>
    <div className="flex">
      <FilterSidebar />               ← captured (defect)
      <div className="flex-1 ...">
        <KPISection />
        <p>Showing X of Y records</p> ← captured (defect)
        <ChartGrid />
        <div data-html2canvas-ignore>...hidden-chart panel...</div>
      </div>
    </div>
  </div>
</section>
```

**Target shape:**

```
<section>
  <header data-html2canvas-ignore>...buttons...</header>
  <div className="flex">
    <FilterSidebar data-html2canvas-ignore />   ← outside sectionRef + belt-and-suspenders marker
    <div ref={sectionRef} className="flex-1 min-w-0 space-y-4">
      {activeFilterCount > 0 && (
        <div className="...chip-row-styles...">
          ...chips: each chip's <X> icon marked data-html2canvas-ignore;
              the trailing Reset button marked data-html2canvas-ignore...
        </div>
      )}
      <KPISection />
      <p data-html2canvas-ignore>Showing X of Y records</p>
      <ChartGrid />
      <div data-html2canvas-ignore>...hidden-chart panel...</div>
    </div>
  </div>
</section>
```

Behavior:

- `sectionRef` now wraps **only the right column**. The FilterSidebar is structurally a sibling, so its width does not appear as empty space in the PNG.
- When `activeFilterCount === 0` the chip row is **not rendered at all** (no DOM, no PNG presence). When ≥1 active, the row renders, and the X icon per chip + the trailing Reset button each carry `data-html2canvas-ignore` so the PNG sees flat chip labels.
- The records indicator is rendered for screen but excluded from the PNG via `data-html2canvas-ignore`.

### `downloadAsPng.ts` signature extension

New optional third argument:

```ts
export async function downloadElementAsPng(
  element: HTMLElement,
  filename: string,
  options?: { backgroundColor?: string; footer?: string | null },
): Promise<void>
```

Backward compatible: per-chart caller (`downloadElementAsPng(el, title)`) continues to work — no footer rendered, no behavioral change.

### Footer painting path

When `options.footer` is a non-empty string:

1. Call `toPng(element, { ... })` to get the dashboard `dataUrl` (current path).
2. Load the dataUrl into an `HTMLImageElement` and await `onload`.
3. Create an offscreen `<canvas>` of width `img.naturalWidth` and height `img.naturalHeight + FOOTER_H * pixelRatio`, where `FOOTER_H = 48` source-px and `pixelRatio = 2` (matches `toPng`'s `pixelRatio: 2`).
4. Paint `backgroundColor` over the whole canvas, then draw the image at (0, 0).
5. Draw the footer text: font `24px ui-sans-serif, system-ui, sans-serif`, fill `#9ca3af` (zinc-400), `textBaseline: "middle"`, position `(40, img.naturalHeight + FOOTER_H)` — i.e., vertically centered in the new bottom band.
6. Export with `canvas.toDataURL("image/png")` and trigger the same `<a download>` click path.

When `options.footer` is null/undefined/empty, skip the canvas step entirely (current path, no perf regression for per-chart export).

### Caller in `handleDownloadAll`

Compute footer + filename from `latest.raw_query`:

```ts
const rawName = latest?.raw_query ? latest.raw_query.slice(0, 60) : "analysis";
const today = new Date().toISOString().split("T")[0];
const footer = `${rawName} · Generated by AnalystAI · ${today}`;
const slug = rawName.toLowerCase().replace(/[^a-z0-9]+/g, "-").replace(/^-|-$/g, "") || "analysis";
const filename = `dashboard_${slug}_${today}`;
await downloadElementAsPng(sectionRef.current, filename, { footer });
```

Rationale for `raw_query` as source: `LatestAnalysis` does not expose a dedicated `dataset_name`. The user's question text is the most recognizable label in scope. Truncated to 60 chars to keep both footer line and filename reasonable.

## Verification matrix

| Scenario | Expected PNG |
|---|---|
| No filters active → click "PNG" | KPI row + chart grid + footer. No sidebar, no chip row, no records text, no header buttons. |
| One equality filter active (click a bar) | Same as above + chip row at top showing chip labels **without** the X icon and **without** the Reset button. Footer present. |
| Multi-kind filters (sidebar slider + cross-filter click) | Chip row shows all active filters with no interactive chrome. KPIs reflect filtered values. Charts re-aggregated. Footer present. |
| Per-chart PNG (hover → "PNG" on a card) | Single chart card only. **No footer.** Filename = chart title slug (unchanged). |
| Edit mode active when full-dashboard PNG triggered | Edit-mode overlay buttons absent from PNG (already marked ignore). Hidden-charts restore panel absent (already marked). |
| `cd frontend && npm run build` | Passes (no TS errors from signature change). |

## Risks / open questions

- **`raw_query` truncation at 60 chars** may produce ugly footers for short queries (fine) but odd-feeling slugs for long ones. Acceptable for v1; can be revisited if users complain.
- **Footer pixel sizing** assumes `pixelRatio: 2`. If the pixel ratio is ever made configurable, the footer-height math (`FOOTER_H * pixelRatio`) needs to follow. Documented inline in the code.
- **No automated tests.** Project has no frontend test runner today (per CLAUDE.md). Verification is manual via the UI + `npm run build` typecheck.

## Out of scope / future

- A dedicated `dataset_name` field on `LatestAnalysis` would yield a cleaner footer/filename — orthogonal change, not part of this gap.
- Multi-page PDF or branded report export — not in this gap; that's a Spec 3+ conversation.
- Bringing report panels back to the dashboard under an "Analysis details" collapsible — explicitly out of scope (user chose "tighten only" path).
