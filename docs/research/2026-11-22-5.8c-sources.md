# Research: 5.8c sources (Stripe, Shopify, HubSpot imports)

Collected 2026-11-22 for Phase 5.8c by a background research agent, primary sources only. It builds on
`docs/research/2026-11-19-data-sources.md` and `2026-11-20-5.8b-sources.md` without repeating them. The decisions
(own fetchers through `public_client`, no dlt, no DuckDB, GA4 cut; Stripe → Shopify Bulk Operations → HubSpot
Service Keys) come from the plan's grilling debate; this file is the evidence. **Verified** = fetched on 2026-11-22;
**UNVERIFIED** = no primary source confirmed it that day. "Corrections to the plan" is at the end.

## 1. Decision record

**Why not dlt** (dlt 1.32.0, [PyPI JSON](https://pypi.org/pypi/dlt/json)):
- Network client: the verified sources don't use `public_client`. `stripe_analytics` requires `stripe>=5.0.0,<16`
  ([requirements](https://raw.githubusercontent.com/dlt-hub/verified-sources/master/sources/stripe_analytics/requirements.txt));
  `shopify_dlt/helpers.py` calls `requests.get(url, …)` via `dlt.sources.helpers.requests`
  ([helpers.py](https://raw.githubusercontent.com/dlt-hub/verified-sources/master/sources/shopify_dlt/helpers.py)).
- Telemetry: "`dlt` collects and reports anonymous usage information"; it writes `~/.dlt/.anonymous_id`; opt-out via
  `--disable-telemetry` or `[runtime] dlthub_telemetry=false` ([telemetry](https://dlthub.com/docs/reference/telemetry)).
- Dependencies: 29 base requirements, incl. `requests>=2.26.0`, `gitpython`, `pendulum`, `setuptools` and a floating
  **`sqlglot>=26.32.0`**, which would float against our pinned SQL guard.

**Why not DuckDB** (duckdb 2.0.1):
- A second CSV sniffer next to `_read_text_table` breaks P58-01 (one reader, one meaning).
- xlsx needs the `excel` extension, "transparently autoloaded on first use from the official extension repository"
  (a network install, [excel](https://duckdb.org/docs/2.0/core_extensions/excel.html)); the repository falls back
  to extensions.duckdb-backup.org ([core extensions](https://duckdb.org/docs/2.0/core_extensions/overview.html)).
- **CVE-2024-41672** (GHSA-w2gf-jxc9-pf2q, Moderate): "sniff_csv provides filesystem access even when
  enable_external_access is disabled", affects 1.0.0, fixed 1.1.0
  ([advisory](https://github.com/duckdb/duckdb/security/advisories/GHSA-w2gf-jxc9-pf2q)): the deny-list pattern again.
- Hardening ([securing DuckDB](https://duckdb.org/docs/2.0/operations_manual/securing_duckdb/overview.html)):
  `enable_external_access=false` blocks `ATTACH`, `COPY` and external `read_csv`/`read_parquet`, after which
  `allowed_paths`/`allowed_directories` can't change; `SET lock_configuration = true` freezes settings outside
  `allowed_configs`; extension autoload/autoinstall default on (`autoload_known_extensions` /
  `autoinstall_known_extensions = false`). "Treat SQL in DuckDB like code in Bash or Python."

## 2. Stripe

**Restricted keys** ([restricted keys](https://docs.stripe.com/keys/restricted-api-keys)): `rk_live_` / `rk_test_`.
Dashboard → [API keys](https://dashboard.stripe.com/apikeys) → **Create restricted key** → name → each resource
**None / Read / Write** (default None) → **Create key** → 2FA → copy (shown once). Write implies Read. Missing
permission: **403** "The API key doesn't have permissions to perform the request" ([errors](https://docs.stripe.com/api/errors)),
and "the response body includes an error message explaining which permissions to add". The Dashboard's exact
resource labels are **UNVERIFIED**: read them off a live restricted-key form before writing the setup steps.

**Lists** ([pagination](https://docs.stripe.com/api/pagination)): `limit` 1–100 (default 10); `starting_after=<last id>`;
`has_more` false = end; reverse chronological. The response's `url` is a path, never a next URL.

**Subscriptions** ([list](https://docs.stripe.com/api/subscriptions/list)): with no `status`, "all subscriptions that
have not been canceled"; `status=all` returns every status. `created[gte]=<unix>` filters.

**Invoice lines**: the invoice's `lines` holds "the total count of line items and the first handful"; the rest via
`GET /v1/invoices/{id}/lines` (limit 1–100, `starting_after`) ([lines](https://docs.stripe.com/api/invoice-line-item/retrieve)).
The handful's size is **UNVERIFIED**: page whenever `lines.has_more`.

**Rate limits** ([rate limits](https://docs.stripe.com/rate-limits)): global live 100 req/s, sandbox 25 req/s; per
endpoint 25 req/s; live concurrency 50 in flight. A 429 carries `Stripe-Rate-Limited-Reason` (`global-rate`,
`endpoint-rate`, `global-concurrency`, `endpoint-concurrency`, `resource-specific`). Reads: "must not exceed an average
of 500 per transaction" over a rolling 30 days, "a minimum allocation of 10,000 read requests per month".

**Errors**: 401 "No valid API key provided"; 403 permission; 429 "Too Many Requests … exponential backoff". Body
`{type, code, message, param, doc_url, request_log_url}`. `Stripe-Should-Retry` true/false/absent
([low-level errors](https://docs.stripe.com/error-low-level)). **No `Retry-After` is documented.**

**Currencies** ([currencies](https://docs.stripe.com/currencies)): zero-decimal **BIF CLP DJF GNF JPY KMF KRW MGA PYG
RWF UGX VND VUV XAF XOF XPF**. Special: **ISK** two-decimal with `00` (500 = 5 ISK); **HUF, TWD** zero-decimal for
payouts only, two-decimal on charges, invoices and prices; **UGX** listed zero-decimal but "backwards compatibility
requires you to represent it as a two-decimal value" (the page contradicts itself). Three-decimal BHD JOD KWD OMR TND
are supported ([support](https://support.stripe.com/questions/which-payments-methods-and-products-are-available-in-the-uae));
whether `amount` is in thousandths is **UNVERIFIED**.

**$0 recordings**: sandbox / test mode (`rk_test_`), 25 req/s.

**Dashboard CSV export**: the Subscriptions tab exports
([report types](https://support.stripe.com/questions/generic-report-types-at-stripe)); its **column names and units are
unpublished (UNVERIFIED)**. Record them from the test account for the oracle; never write them from memory.

## 3. Shopify

**Legacy custom apps**: "Starting January 1, 2026, you can no longer create new custom apps in the Shopify admin";
existing ones keep working ([changelog](https://shopify.dev/changelog/legacy-custom-apps-can-t-be-created-after-january-1-2026)).

**Client credentials grant** ([doc](https://shopify.dev/docs/apps/build/authentication-authorization/access-tokens/client-credentials-grant)):
works "only when the app and the store belong to the same Shopify organization". Dev Dashboard: create the app,
choose scopes on a version, install on the store; copy Client ID and secret from Settings. Then
`POST https://{shop}.myshopify.com/admin/oauth/access_token` (form `grant_type=client_credentials&client_id&client_secret`,
no `scope`); `expires_in` 86399 s; header `X-Shopify-Access-Token`.

**Scopes** ([access scopes](https://shopify.dev/docs/api/usage/access-scopes)): `read_orders` = last 60 days;
`read_all_orders` "doesn't grant access on its own" (with `read_orders`). "Dev Dashboard apps under a merchant
organization don't need Shopify approval"; Partner-organization apps do.

**Bulk Operations** ([bulk queries](https://shopify.dev/docs/api/usage/bulk-operations/queries)):
`bulkOperationRunQuery` → `id`, status `CREATED`. From API **2026-01**, "up to five bulk query operations per shop
simultaneously"; poll `bulkOperation(id:)` (`currentBulkOperation` deprecated); the finish webhook isn't guaranteed.
JSONL, one node per line; nested items carry `__parentId` and "appear after their parents" (not immediately after).
`url` / `partialDataUrl` "signed (authenticated) and will expire after one week" (examples on
`storage.googleapis.com`). ≤ 10 days, ≤ 5 connections, 2 levels of nesting. `objectCount` is a running total.

**Order fields** ([Order](https://shopify.dev/docs/api/admin-graphql/latest/objects/Order)): `test` (Bogus Gateway
or a test-mode provider); `retailLocation` (null for draft POS orders marked paid; `physicalLocation` deprecated);
`currencyCode` (shop) vs `presentmentCurrencyCode`; `createdAt`, `processedAt`, `cancelledAt` ISO 8601. `Decimal` is
"serialized as a string" ([Decimal](https://shopify.dev/docs/api/admin-graphql/latest/scalars/Decimal)).

**Dev stores** ([dev stores](https://shopify.dev/docs/api/development-stores)): Dev Dashboard → Stores → Create store
→ Dev; `shopify store create dev --demo-data`; test payment gateway; 250 per organization; cost unstated (UNVERIFIED).

**Orders CSV export** ([help](https://help.shopify.com/en/manual/fulfillment/managing-orders/exporting-orders)):
**one row per line item**, extra rows with "many of the fields … left blank". Columns include `Name, Email,
Financial Status, Paid at, Fulfillment Status, Currency, Subtotal, Shipping, Taxes, Total, Discount Code, Discount
Amount, Created at, Lineitem quantity, Lineitem name, Lineitem price, Lineitem SKU, …, Billing *, Shipping *,
Canceled at, Refunded Amount, Vendor, Employee, Location, Id, Tags, Source, Lineitem discount`. **No test column.**
Exports over 50 orders are emailed.

## 4. HubSpot

**Service Keys**: "Announced: Feb 10, 2026 … public beta" ([changelog](https://developers.hubspot.com/changelog/service-keys)).
Development → Keys → Service keys → Create service key → name → scopes → Create (super admins or Developer tools
permission); a key gets only scopes its creator holds; `Authorization: Bearer pat-…`; ≤ 100 apps+keys+MCP per
account; REST only; rotation every 3/6/12 months or manual with a 7-day grace
([doc](https://developers.hubspot.com/docs/apps/developer-platform/build-apps/authentication/account-service-keys)).

**Scopes** ([scopes](https://developers.hubspot.com/docs/apps/developer-platform/build-apps/authentication/scopes)):
`crm.objects.deals.read`, `crm.objects.owners.read`, "Available to all accounts".

**Deals** ([GET deals](https://developers.hubspot.com/docs/api-reference/latest/crm/objects/deals/get-deals.md)):
`after` from `paging.next.after`; `limit` default 10, **maximum unstated (UNVERIFIED)**; `id` is a string;
`dealstage`/`pipeline` are internal ids ([guide](https://developers.hubspot.com/docs/api-reference/crm-deals-v3/guide)).
Search: 5 req/s, ≤ 200/page, **10,000-result cap** (400 past it), indexing lag
([search](https://developers.hubspot.com/docs/api-reference/search/guide)): list paging for a full import.

**Labels**: `GET /crm/v3/pipelines/deals` → pipelines and stages with `id`, `label`, `displayOrder`
([pipelines](https://developers.hubspot.com/docs/api-reference/crm-pipelines-v3/guide)); `GET /crm/v3/owners` (`id`
for ownership; `archived=true` keeps deactivated owners' `id`, `userId` null)
([owners](https://developers.hubspot.com/docs/api-reference/crm-crm-owners-v3/guide.md)).

**Ids**: strings in v3; stored as 64-bit unsigned per HubSpot staff ([community](https://community.hubspot.com/t/id-ranges/16349));
ids > 2**53 in practice UNVERIFIED. Keep `exact_whole_numbers`; never parse to float.

**Rate limits** ([usage guidelines](https://developers.hubspot.com/docs/developer-tooling/platform/usage-guidelines)):

| Tier (privately distributed) | per 10 s, per app | per day, per account |
|---|---|---|
| Free and Starter | 100 | 250,000 |
| Professional | 190 | 625,000 |
| Enterprise | 190 | 1,000,000 |

Service keys share them. 429 body `{status, message, errorType: "RATE_LIMIT", correlationId, policyName, requestId}`;
headers `X-HubSpot-RateLimit-Max/-Remaining/-Interval-Milliseconds/-Daily/-Daily-Remaining`. **No `Retry-After`.**

**$0 recordings** ([account types](https://developers.hubspot.com/docs/getting-started/account-types)): developer test
accounts, free, up to 10; expire after 90 days without API calls (renewable).

## 6. Peers: freshness and failure display
- **Airbyte** ([connection status](https://docs.airbyte.com/platform/cloud/managing-airbyte-cloud/review-connection-status)):
  Healthy / Failed / Running / Paused / Queued; per stream the time since the last record loaded; configuration
  errors red ("re-test and save"), system errors yellow; rate limits a countdown; repeated failures auto-disable.
- **Rill**: a Status page lists each resource's error; `rill project status` shows last refresh dates
  ([maintenance](https://docs.rilldata.com/tutorials/administration/project/project-maintanence)); its failed-refresh
  view is UNVERIFIED.
- **Metabase** ([sync](https://www.metabase.com/docs/latest/databases/sync-scan)): Admin → Tools → Tasks; a manual
  "Sync database schema"; no per-source "last synced" badge documented.
- **Evidence**: no freshness display found (UNVERIFIED).

Common pattern: the last successful load beside a status, one error per failure with a fix action, old data kept:
the plan's Q1 (stale with time and reason, last good kept).

## 7. Memory
- Wes McKinney: "you should have **5 to 10 times as much RAM as the size of your dataset**"
  ([blog](https://wesmckinney.com/blog/apache-arrow-pandas-internals/)); pandas' docs give levers, no ratio
  ([scale](https://pandas.pydata.org/docs/user_guide/scale.html)). Measure `peak_mb()`; at 5–10×, 150 MB ≈ 0.75–1.5 GB.
- Starlette's `UploadFile.file` is a `SpooledTemporaryFile`, `spool_max_size = 1 MB`, files "not limited by
  `max_part_size`" ([formparsers.py](https://raw.githubusercontent.com/encode/starlette/master/starlette/formparsers.py),
  [requests.md](https://raw.githubusercontent.com/encode/starlette/master/docs/requests.md)); `request.stream()` yields
  chunks without storing the body; FastAPI: memory up to a limit, then disk
  ([FastAPI](https://fastapi.tiangolo.com/tutorial/request-files/)). Today's 2× comes from the chunk list plus
  `b"".join`; the multipart body is already on disk before the route's own cap check (red-team finding 5).

## Corrections to the plan (folded in)
1. **429**: neither Stripe nor HubSpot documents `Retry-After`. The one retry honours it when present, else a fixed
   bounded backoff; never retry on `Stripe-Should-Retry: false` or HubSpot `policyName` DAILY.
2. **Currency special cases** (UGX, HUF, TWD, ISK, three-decimal): settled from a test-mode recording each, not docs.
3. **Export columns**: Stripe's are unpublished (record from test mode); Shopify's orders export has no `test`
   column, so the test marker comes from the API's `test` field.
4. **Shopify**: a merchant-owned Dev Dashboard app needs no approval for `read_all_orders`; 5 bulk queries per shop
   from 2026-01 (not 1).
