## 1. Grain of typical extracts

- **Sensor time series, long ("narrow") form**: one row = one tag (sensor/property) × one timestamp
  × one value (+ quality). Ignition: `tagid, intvalue|floatvalue|stringvalue|datevalue,
  dataintegrity, t_stamp` [IGT]; SiteWise: TQV = "timestamp-quality-value" per asset property
  [SWB]; PI: `Timestamp, Value, UnitsAbbreviation, Good, Questionable, Substituted` per stream [PIV].
  Rows per tag are irregular: historians store **on change** beyond a deadband, so "if the value
  doesn't change, a new row is never inserted" [IGC, IGH]; PI's compression "drops events it
  doesn't need to rebuild the signal" [PIC]. A missing row is not a missing reading.
- **Sensor time series, wide form** (one row = one timestamp, one column per sensor): usually an
  export already resampled/interpolated to a fixed interval (PI `GetInterpolated` "at the specified
  sampling interval" [PIA]; Ignition fills empty slices: "interpolation will create a value" [IGH]).
  Values in it may be computed, not measured.
- **Events / alarms / state changes**: one row = one state transition or alarm (asset, start
  timestamp, end timestamp or duration, state/reason code). Durations are intervals; counts of rows
  are counts of transitions, not of time (**unverified**, convention).
- **Work orders (CMMS)**: one row = one work order (Maximo key "SiteID and WoNum" [MXW]); failure
  codes may live on a child table, one row per hierarchy level per WO (FAILUREREPORT: `WoNum`,
  `FailureCode`, `Type` = "level of the failure code" [MXF]). Not every WO is a failure: `WorkType`
  separates corrective from preventive etc. [MXW], and `DownTime` "indicates if the asset has to be
  down" [MXW].
- **Production counts**: one row = one shift × line (or order × operation) with planned time, run
  time / downtime minutes, total count, good count, reject/scrap count, ideal cycle time [OC, OPCK].
  OEE inputs PBT and PRI "usually come from an MES or ERP and not from the machine" [OPCK].
- **Run-to-failure / predictive-maintenance samples** (e.g. one row per unit-cycle with sensor
  readings and a failure flag or RUL): the share of failed rows is not a failure rate; units still
  running at the end are right-censored [NRC].

## 2. Definitions (exact)

### 2.1 OEE (ISO 22400-2 via OPC 40501-1; oee.com)
- ISO 22400-2 form [OPCK]: Availability = APT / PBT; Effectiveness = PRI × PQ / APT;
  Quality rate = GQ / PQ; OEE = Availability × Effectiveness × Quality rate.
  APT = actual production time; PBT = planned busy time; PRI = planned run time per item;
  PQ = produced quantity; GQ = good quantity; SQ (scrap) = PQ − GQ; RQ = rework quantity [OPCK].
  ("Effectiveness" in ISO = "Performance" in common OEE usage.)
- oee.com form [OC]: Availability = Run Time / Planned Production Time; Performance = (Ideal Cycle
  Time × Total Count) / Run Time; Quality = Good Count / Total Count; OEE = A × P × Q, which
  simplifies to (Good Count × Ideal Cycle Time) / Planned Production Time [OC].
  Planned Production Time = shift length − breaks; Run Time = Planned Production Time − Stop Time
  (unplanned and planned stops such as changeovers); Ideal Cycle Time = "the fastest cycle time
  that your process can achieve in optimal circumstances"; Good Count = Total Count − Reject Count [OC].
- Counting unit: parts (or units of product), time in one consistent unit. Period basis: the shift,
  day or order; the denominator is planned time, not calendar time.
- Exclusions: periods with "no intent to run" (breaks, unscheduled shifts) are out of the
  denominator [OC]; changeovers and preventive maintenance are **in** (Availability loss) [OF].
- Performance > 100% means the ideal cycle time is wrong (set too slow), not a super-performance
  (**unverified**, convention following from the definition [OC]).
- TEEP = A × P × Q × Utilization, "the ratio of Fully Productive Time to All Time (24/7)" [OF].
- Measure OEE "at the constraint step"; OEE at every step gives "conflicting information" [OF].

### 2.2 Availability, Performance, Quality, yields, scrap, defects
- Availability, Performance, Quality: §2.1. Quality counts first-pass good: good parts "pass through
  the manufacturing process the first time without needing any rework" [OC] (so ≈ first-pass yield).
- First-pass yield (FPY) = units good first time ÷ units started at one step; reworked units are
  not first-pass good. Final yield counts reworked-then-good units. Rolled throughput yield (RTY) =
  product of step FPYs (**unverified**: ASQ glossary not read; secondary sources disagree on the
  naming, one calls RTY "first pass yield").
- Scrap rate = SQ / PQ = (PQ − GQ) / PQ [OPCK] if rework is counted as good; state the rework rule.
- Defect rate: defective units ÷ units (ppm = × 10^6) vs DPMO = defects ÷ (units × opportunities
  per unit) × 10^6. A unit can carry several defects; ppm-defective and DPMO are not comparable
  (**unverified**, Six Sigma convention).

### 2.3 Reliability: failure, MTBF, MTTF, MTTR, failure rate, censoring
- Failure = "loss of ability to perform as required"; a failure is an event that results in a
  fault (a state) [IEV, snippet]. A stop is not a failure unless the item lost its required
  function: a planned stop, a changeover, a starved/blocked stop or an operator pause is not.
- MTBF (repairable, constant rate): HPP model, ROCOF = constant λ, MTBF = 1/λ [NRH].
  Point estimate = "Total System(s) operation time ÷ Total number of failures"; hours of several
  units are pooled (800 h, 2 failures → 400 h; 90% CI ≈ 127–2,251 h) [NRM]. Zero failures: only
  a lower bound, T / (−ln α) (800 h at 95% → ≈ 267 h) [NRM]. The numerator is **operating**
  time, not calendar time (SEMI E10: "productive time divided by the number of failures" [E10, snippet]).
- HPP fits only the flat part of the bathtub curve: "The HPP is the only model that applies to that
  portion of the curve" [NRH, NRB]. An MTBF on a wearing-out or infant-mortality fleet is a
  misleading single number.
- MTTF: mean time to (first) failure of a non-repairable item; MTBF: between failures of a
  repairable one (**unverified** wording; IEV entries not readable). Do not mix them.
- MTTR (SMRP 3.5.2) = total repair or replacement time ÷ number of repair events, and SMRP/EN
  include administrative and logistic delay [SMRP, snippet]; MIL-HDBK-338B "active repair" MTTR
  excludes them (snippet). State which.
- Failure rate = failures ÷ unit operating time (per hour, per 10^6 h); it is λ in the HPP [NRH].
  A share of units that failed is not a rate.
- Censoring: "When not all units on test fail we have censored data"; units that "survived the
  entire T-hour test without failing" are right-censored and their hours still count [NRC].
  Estimate with Kaplan-Meier or MLE [NRC], never by dropping survivors.

### 2.4 Downtime taxonomies, six big losses, micro-stops, uptime
- Six big losses [OL]: Availability = Equipment Failure (unplanned stops), Setup and Adjustments
  (planned stops); Performance = Idling and Minor Stops (small stops), Reduced Speed (slow cycles);
  Quality = Process Defects (stable production), Reduced Yield (start-up until stable).
- Small/micro-stops: "well under five minutes", resolved by the operator, no maintenance [OL]. The
  threshold is site-defined: many systems record a stop as downtime only past a threshold, so
  micro-stops hide inside Performance loss (**unverified**, convention).
- SEMI E10 six states [E10, snippet]: non-scheduled, unscheduled downtime, scheduled downtime,
  engineering, standby, productive. Uptime = engineering + standby + productive; manufacturing time
  = productive + standby. MTBI (between interrupts) is separate from MTBF.
- Planned vs unplanned: planned (PM, changeover, cleaning) is still an Availability loss in OEE
  [OF]; it is excluded only when "no intent to run" (breaks, unscheduled shifts) [OC].

### 2.5 SPC: control limits, run rules, capability
- Individuals chart: MR_i = |x_i − x_(i−1)|; limits x̄ ± 3·MR̄/1.128, where "1.128 is the value of
  d2 for n = 2" [NPI]. MR chart: UCL = D4·MR̄ with D4 = 3.267 for n = 2, LCL = 0 (D3 = 0) [NPR].
  Alternative: x̄ ± 3s/c4 [NPI]. (3/1.128 = 2.66.)
- Western Electric rules [NPW]: 1 point beyond 3σ; 2 of 3 beyond 2σ (same side); 4 of 5 beyond 1σ
  (same side); 8 consecutive on one side of the centre line; plus trend rules "6 in a row trending
  up or down. 14 in a row alternating". Cost: false alarms rise from ~1 per 371 points (3σ only) to
  ~1 per 91.75 points with WECO rules [NPW].
- Nelson / Minitab eight tests [MTS]: 1 point > 3σ; **9** in a row same side; 6 in a row
  increasing/decreasing; 14 alternating; 2 of 3 > 2σ same side; 4 of 5 > 1σ same side; 15 in a row
  within 1σ; 8 in a row > 1σ either side. "Adding more tests … may also increase the chance of
  getting a false signal" [MTS]. WECO run = 8, Nelson run = 9: name the rule set.
- Control vs spec limits: "Control Limits are used to determine if the process is in a state of
  statistical control"; "Specification Limits are used to determine if the product will function in
  the intended fashion" [NPW]. Control limits come from the data; spec limits come from engineering.
- Capability [NPC]: Cp = (USL − LSL) / 6σ; Cpk = min[(USL − μ)/3σ, (μ − LSL)/3σ]; Cpm uses
  sqrt(σ² + (μ − T)²). Requires "an in-control process", assumes normality (else Box-Cox or
  nonparametric indices), ~50 independent values, n ≥ 100 for capability studies [NPC].
- Cp/Cpk use within-subgroup σ (pooled; moving range for n = 1); Pp/Ppk use the overall σ of all
  data [MTB]. Ppk < Cpk signals drift between subgroups (Minitab blog, secondary).
- Independence: Shewhart charts assume independent observations; high-frequency sensor data are
  autocorrelated and give false alarms (NIST-hosted Zhang & Pintar abstract, snippet).

### 2.6 Ratio KPIs are non-additive: how to aggregate
- OEE, Availability, Performance, Quality, yield, MTBF are ratios. Across lines/machines/shifts/days:
  sum numerators and denominators, then divide. oee.com: "A simple average of individual OEE scores
  is insufficient"; sum Run Time, Planned Production Time, Ideal Cycle Time × count, Total and Good
  parts, then recompute [OF]; a plant OEE may be a weighted average with weights of "time (e.g.,
  Planned Production Time) or value" [OF]. MachineMetrics weights each component separately
  (scheduled time, ideal part time, part counts) [MM, snippet].
- Correct roll-ups: Availability = Σ run time / Σ planned time; Performance = Σ(ideal CT × count) /
  Σ run time; Quality = Σ good / Σ total; OEE = their product (= Σ(good × ideal CT) / Σ planned
  time). Plant OEE ≠ mean(line OEE) and ≠ mean(A) × mean(P) × mean(Q).
- MTBF across assets = Σ operating hours / Σ failures [NRM], not mean of asset MTBFs.
- Sensor averages: time-weighted when sampling is irregular. PI summaries default to
  `calculationBasis = TimeWeighted` [PIA]; an event-weighted mean of on-change data over-weights
  periods of change (**unverified** beyond the PI default).

## 3. Benchmarks (context only, never a verdict)

- "World-class OEE 85%" = 90% Availability × 95% Performance × 99% Quality (≈ 84.6%); figures from
  Seiichi Nakajima (*Introduction to TPM*, 1984), "based on his practical experience, as minimums
  for which companies should strive" [OW]. Caveats from the same page: one country (Japan), one
  period (1970s), one industry (automotive), discrete manufacturing; "Don't fixate on the absolute
  value"; typical manufacturers are "closer to 60%"; high-mix lines lose more to changeovers [OW].
  Book itself not read: the 85% origin is secondary (oee.com).
- Why never a verdict: OEE depends on the site's choice of ideal cycle time, of what counts as
  planned time and of the stop threshold (§2.1, §2.4); two plants' OEE are not comparable [OW, OF].
- Cpk ≥ 1.33 as a "capable" target is a customer/industry convention (AIAG PPAP), not a law
  (**unverified**, AIAG manual not read).
- WECO and Nelson run rules are tests with known false-alarm rates [NPW, MTS]: a rule violation is a
  signal to investigate, not proof of a special cause.

## 4. Traps (with the authority that warns)

1. **Missing rows read as dropouts** (or dropouts read as steady values). On-change historians write
   no row while the value is inside the deadband [IGC, IGH]; compressed PI archives drop events
   reconstructible by interpolation [PIC]. A gap needs the tag's deadband / max-time setting before
   it is called a dropout. Conversely a real outage leaves a gap that interpolation silently fills [IGH].
2. **Interpolated values treated as measurements.** `GetInterpolated` computes values at an interval;
   `GetRecorded` returns stored ("compressed") values [PIA]; Ignition creates values for empty slices
   [IGH]. Extremes (peaks) are lost by interpolation; counts of rows in a resampled file are not
   counts of readings.
3. **Truncated pulls**: PI `GetRecorded` `maxCount` defaults to 1000 [PIA]: an export of exactly
   1000 (or a round number of) rows per tag may be cut off.
4. **Quality flags ignored.** OPC UA: Uncertain "shall be used with care"; Bad "shall never be used";
   reserved severity is treated as Bad [OPCS]. Ignition `dataintegrity` 192 = good, "anything else is
   bad" [IGT]. SiteWise `quality` ∈ GOOD | BAD | UNCERTAIN [SWV]. PI `Good`, `Questionable`,
   `Substituted` booleans [PIV]; PI may return a "Filtered" enumeration value [PIR]. Never average a
   digital state ("Filtered", "Shutdown", "I/O Timeout") as a number (**unverified** for the state names).
5. **Stuck-at / flatline**: a sensor repeating the exact same value for far longer than its noise
   allows is a fault, not a stable process; and on-change storage makes a flatline look like a gap
   (**unverified**, convention).
6. **Mixed units** (°C/°F, psi/bar, mm/in) across tags or after a sensor swap: PI carries
   `UnitsAbbreviation` per value [PIV]; check it before combining (**unverified** as a frequency claim).
7. **DST**: "When clocks are moved back … a fold"; "When the clocks are moved forward, a gap";
   local times in the fold are "ambiguous", in the gap "missing" [PEP]. A local-time export has a
   repeated hour in autumn (duplicate timestamps, 25-hour day) and a missing hour in spring
   (23-hour day): shift lengths and daily totals shift by an hour. Ignition `t_stamp` (ms since epoch)
   [IGT] and SiteWise `timeInSeconds` (Unix epoch) [SWT] are UTC; work in UTC, convert for display.
8. **UTC vs local**: PI time strings are interpreted in a `timeZone` parameter [PIA]; a CSV without
   an offset may be either. Shift and day boundaries are local, storage is UTC.
9. **Duplicate timestamps**: SiteWise "overwrites TQVs with duplicate timestamps unless the newer TQV
   has a different quality" [SWB]; in a flat file duplicates may be DST folds, re-sent messages or
   two qualities. Deduplicate by (tag, timestamp, quality) after deciding which.
10. **Late / out-of-window data**: SiteWise accepts only "[-7 days, +10 minutes]" around ingest
    [SWB]: buffered edge data older than 7 days was rejected, not absent from the process.
11. **Shifts spanning midnight**: a night shift 22:00–06:00 belongs to one production day; grouping
    by calendar date splits it (**unverified**, convention). Assign shift by a shift calendar.
12. **Sampling-rate changes**: a tag reconfigured from 1 s to 60 s changes row counts, apparent
    variance and alarm counts; resampling up-samples by interpolation and down-samples by an
    aggregation method that must be named [IGH] (**unverified** for the variance effect).
13. **Counter resets / rollover**: cumulative counters (part count, run hours, energy) drop to 0 on
    PLC restart or overflow. Prometheus: "Any decrease in the value between two consecutive float
    samples is interpreted as a counter reset"; rate/increase adjust for "breaks in monotonicity"
    [PROM]. Differencing raw counters without reset handling gives negative production.
14. **Ratio of averages vs average of ratios** (§2.6) [OF].
15. **Performance > 100% / OEE > 100%**: the ideal cycle time is too slow (§2.1).
16. **Planned downtime moved out of the denominator** to inflate Availability; changeovers and PM
    belong in Availability loss [OF].
17. **Failure = any stop / any work order**: preventive WOs, inspections and starved/blocked stops are
    not failures [IEV, MXW]; filter on WorkType and the failure-code hierarchy [MXW, MXF].
18. **Censoring ignored**: MTBF/MTTF from failed units only, dropping survivors, biases toward short
    lives [NRC]. Survivorship: assets replaced early or scrapped vanish from the asset list.
19. **Constant-rate MTBF on a non-constant process** [NRH, NRB].
20. **Control limits computed from spec limits** (or spec used as control) [NPW]; Cpk on an unstable
    or non-normal process [NPC]; Cpk vs Ppk confused [MTB].
21. **Autocorrelated high-frequency data on a Shewhart chart**: limits too tight, false alarms
    (snippet, NIST-hosted abstracts).
22. **Causal claims from sensor correlations**: "vibration causes failure" or "S07 fails because it
    drifts" from observational data; the drift may be a symptom of the same degradation, of a
    different duty cycle, or of a sensor fault (**unverified** as a sourced rule; product rule from
    the other domains).
23. **Benchmark as verdict** ("below world-class 85%") [OW].

## 5. Must say / must never say (senior reliability / manufacturing engineer)

Must say:
- The time basis of every ratio: planned production time vs calendar time vs operating time [OC, NRM].
- What counts as a failure, downtime and a micro-stop at this site (threshold), and that planned
  stops are Availability loss [OF, OL].
- The ideal cycle time source and that Performance > 100% means it is wrong [OC].
- How ratios were rolled up across lines/shifts (summed components) [OF].
- The quality-flag rule applied (Bad excluded, Uncertain flagged) and how many rows it removed [OPCS].
- Recorded vs interpolated and the resampling interval/aggregation method [PIA, IGH].
- Time zone and DST handling; shift calendar used [PEP].
- For MTBF/MTTF: total operating hours, failure count, censored units, the confidence interval, and
  the constant-rate assumption [NRM, NRC, NRH]; which MTTR (with or without logistic delay) [SMRP].
- For SPC: chart type, σ estimator (MR̄/1.128), rule set (WECO 8-run or Nelson 9-run), and that
  control limits are not spec limits [NPI, NPW, MTS].
- Benchmarks as context with their origin (Nakajima, 1970s Japanese automotive) [OW].

Must never say:
- A mean of OEE (or availability, yield, MTBF) percentages as the plant figure [OF].
- MTBF from calendar time, from failed units only, or with zero failures as a point value [NRM, NRC].
- "Out of control" from a spec-limit breach, or "in spec" from a control chart [NPW].
- A Cpk on unstable or n < ~50 data without saying so [NPC].
- A sensor dropout, a dropout rate, or "steady" from missing rows without the historian storage rule [IGC, PIC].
- An interpolated peak/min as measured [PIA].
- Causal statements ("vibration causes failure", "S07 fails because it drifts") from observational
  sensor data; say "associated with", and name the alternative explanations.
- "Below world-class" or any benchmark as a verdict [OW].

## 8. Defaults chosen for the pack (where sources disagree)

| Question | Sources | Default |
|---|---|---|
| OEE formula | ISO 22400 A × Effectiveness × Q [OPCK] vs oee.com A × P × Q [OC] | oee.com names, ISO formulas (identical maths); label "Performance (ISO: effectiveness)" |
| Denominator time | planned production time [OC] vs all time (TEEP) [OF] | planned production time; TEEP only when calendar time is given |
| Changeovers, PM | Availability loss [OF] | in Availability loss; breaks / no-intent-to-run out |
| Quality basis | first-pass good [OC] vs final good | first-pass; report final yield separately when rework is known |
| Roll-up | weighted avg [OF] vs summed components [OF, MM] | summed components, then multiply; never mean of ratios |
| Micro-stop threshold | "well under five minutes" [OL] vs site rule | use the dataset's own reason codes; else report stops < 5 min separately and say so |
| MTBF numerator | operating time [NRM, E10] vs calendar | operating time; calendar only labelled "mean calendar time between failures" |
| MTTR | SMRP incl. delay [SMRP] vs active repair | WO ACTSTART→ACTFINISH, labelled "incl. waiting"; active repair only if labour hours exist |
| Failure | IEV loss of function [IEV] vs any stop/WO | corrective WOs with a failure code, or stop reasons coded as breakdown; never all stops |
| Censoring | KM/MLE [NRC] | report censored units; MTBF = Σ hours incl. survivors ÷ failures; zero failures → lower bound only |
| Run rule set | WECO 8-run [NPW] vs Nelson 9-run [MTS] | rule 1 (3σ) only by default; WECO when asked, named; never all eight unprompted (false alarms) |
| I-chart σ | MR̄/1.128 [NPI] vs s/c4 [NPI] | MR̄/1.128 |
| Capability | Cpk (within σ) vs Ppk (overall σ) [MTB] | report Ppk from a flat export (no rational subgroups); Cpk only with subgroups + stability |
| Quality flags | OPC UA Bad never, Uncertain with care [OPCS] | drop Bad; keep Uncertain but flag the count |
| Time zone | epoch UTC [IGT, SWT] | store/compute in UTC; shift/day boundaries in the site's local zone, DST-aware |
| Resampling | time-weighted (PI default) [PIA] | time-weighted mean for analog tags; last-value for states/counters |
| Counters | reset on decrease [PROM] | diff with reset handling; a decrease = reset, not negative output |
| Benchmarks | Nakajima 85% [OW] | context only, with origin; never a verdict |
