# Research: 5.8b sources (MariaDB, SQL Server, share links)

Collected 2026-11-20 for Phase 5.8b by a background research agent on primary sources; it builds on
`docs/research/2026-11-19-data-sources.md` and doesn't repeat it. **Verified here** means run on this
machine (sqlglot 30.25.0, SQLAlchemy 2.0.49, PyMySQL 2.2.8, httpx 0.28.1 / httpcore 1.0.9, CPython 3.11.14,
expat 2.7.4) or fetched with `curl` on 2026-11-20. **UNVERIFIED** means not confirmed from a primary
source in that session. **The build's corrections and findings are in "Addendum" at the end**: where
the two disagree, the addendum is what the code does and why.

## 1. MariaDB vs MySQL for our row

| Item | MySQL 8.x (our row) | MariaDB 10.6 / 10.11 / 11.4 |
|---|---|---|
| Statement timeout | `SET SESSION max_execution_time = {ms}` (ms, SELECT only) | `SET SESSION max_statement_time = N`: seconds, a double. It "can kill any queries (excluding stored procedures)". `MAX_EXECUTION_TIME` hint only from 12.0. [aborting-statements](https://mariadb.com/kb/en/aborting-statements/) |
| `max_execution_time` on MariaDB | n/a | Not a MariaDB variable: **1193 `Unknown system variable`** ([codes 1100–1199](https://mariadb.com/kb/en/mariadb-error-codes-1100-to-1199/)) |
| Read only | `SET SESSION TRANSACTION READ ONLY`; `START TRANSACTION READ ONLY` | Both exist ([set-transaction](https://mariadb.com/kb/en/set-transaction/), [start-transaction](https://mariadb.com/kb/en/start-transaction/)) |
| Write in a read-only txn | 1792 | Same, 1792 ([codes 1700–1799](https://mariadb.com/kb/en/mariadb-error-codes-1700-to-1799/)) |
| Executable comments | `/*! */` | also **`/*M! */`**, which still runs where `/*!5xxxx` is skipped ([comment-syntax](https://mariadb.com/kb/en/comment-syntax/)); the guard refuses all three openers |
| Default `sql_mode` | — | `STRICT_TRANS_TABLES, ERROR_FOR_DIVISION_BY_ZERO, NO_AUTO_CREATE_USER, NO_ENGINE_SUBSTITUTION`; no `NO_ZERO_DATE`, so zero dates are accepted ([sql-mode](https://mariadb.com/kb/en/sql-mode/)) |
| Cursor types | PyMySQL `TINY=1`, `DATE=10` | the same wire protocol and decoder (UNVERIFIED then; verified in the build) |

SQLAlchemy (verified): `mariadb+pymysql://` gives dialect `mariadb`, `is_mariadb=True`; `mysql+pymysql://` at a
MariaDB server keeps `dialect.name == "mysql"` and only sets `is_mariadb` on first connect
(`sqlalchemy/dialects/mysql/base.py` L2912–2935); `mariadb://` against MySQL raises `InvalidRequestError` (fails
closed). sqlglot has no MariaDB dialect: parse as `mysql`.

## 2. SQL Server: read only and the timeout

**No session or transaction statement makes T-SQL writes fail on a primary.**
- `ApplicationIntent=ReadOnly` is a routing hint for availability-group secondaries; on a primary the connection
  succeeds ([AG listener](https://learn.microsoft.com/en-us/sql/database-engine/availability-groups/windows/listeners-client-connectivity-application-failover)).
- `SET TRANSACTION ISOLATION LEVEL SNAPSHOT` allows writes ([isolation](https://learn.microsoft.com/en-us/sql/t-sql/statements/set-transaction-isolation-level-transact-sql)).
- `SET QUERY_GOVERNOR_COST_LIMIT` caps an estimate, not time ([doc](https://learn.microsoft.com/en-us/sql/t-sql/statements/set-query-governor-cost-limit-transact-sql)).
- `BEGIN TRAN … ROLLBACK` undoes DML but not IDENTITY/SEQUENCE consumption (UNVERIFIED).
- Timeout: no server-side statement timeout; `SET LOCK_TIMEOUT` bounds lock waits only; the query timeout is the
  driver's (pyodbc `Connection.timeout`; [ODBC keywords](https://learn.microsoft.com/en-us/sql/connect/odbc/dsn-connection-string-attribute)).
- Peers: Metabase recommends a read-only user ([Metabase SQL Server](https://www.metabase.com/docs/latest/databases/connections/sql-server));
  Superset sets nothing read-only, allowlists URL keys and denies functions
  ([mssql.py](https://raw.githubusercontent.com/apache/superset/master/superset/db_engine_specs/mssql.py)).

So the only fail-closed read-only layer is **the login**: a session-start check that THROWs when the login can
write, after which a write on a reader login fails with permission denied (229). `HAS_PERMS_BY_NAME`
([doc](https://learn.microsoft.com/en-us/sql/t-sql/functions/has-perms-by-name-transact-sql)), `IS_ROLEMEMBER`,
`IS_SRVROLEMEMBER`.

## 3. SQL Server driver

| | pymssql 2.4.6 | pyodbc 5.5.0 + msodbcsql18 | python-tds 1.17.1 + sqlalchemy-pytds 1.0.3 |
|---|---|---|---|
| Licence | LGPL-2.1 | pyodbc MIT-0; driver under Microsoft's EULA | MIT / MIT |
| Image cost | ~50 MB unpacked, bundling **OpenSSL 1.1.1k (EOL 2023-09)** | Microsoft apt repo + `msodbcsql18` + `unixodbc` | ~0.2 MB, but pyOpenSSL forces `cryptography>=49` |
| TLS to a pinned IP, name verified | no hostname knob | **`HostNameInCertificate`** | `tls_hostname` |
| SQLAlchemy | built in | built in, the primary dialect | third-party |

Cursor values: BIT arrives as `bool`, DECIMAL/MONEY as `Decimal`, so the row needs no yes/no or date predicate.
sqlglot `tsql` (verified): `TOP` parses; `db.dbo.t` is catalog/db/name; a 4-part name is a `Dot`;
`OPENROWSET(BULK …)`, `WAITFOR`, `::fn_*`, `EXECUTE AS` don't parse (fail closed); `EXEC` is not a Query;
`WITH (UPDLOCK)` and `NEXT VALUE FOR` parsed and passed the 5.8a guard.

## 4. T-SQL attack surface for a SELECT-only guard

Corpus: [PayloadsAllTheThings MSSQL](https://github.com/swisskyrepo/PayloadsAllTheThings/blob/master/SQL%20Injection/MSSQL%20Injection.md) (MIT).
File read (`OPENROWSET(BULK`), command execution (`xp_cmdshell`, `sp_*` via EXEC), out-of-band DNS/SMB
(`xp_dirtree`, `xp_fileexist`; table-valued `fn_xe_file_target_read_file`, `fn_get_audit_file`, `fn_trace_gettable`
callable in FROM), linked servers (`OPENQUERY`, `OPENDATASOURCE`, 4-part names), delay (`WAITFOR`), side effects
in a SELECT (`NEXT VALUE FOR`, `UPDLOCK/XLOCK/TABLOCKX/HOLDLOCK`), information (`sys.dm_*`, `master.dbo.*`,
`SERVERPROPERTY`, `SUSER_SNAME`). Role schemas to keep out of the table list: `sys`, `INFORMATION_SCHEMA`, `guest`,
`db_*` (case-insensitive).

## 5. Function allow list

Peers deny; none found allows (Superset `DISALLOWED_SQL_FUNCTIONS`,
[config.py](https://raw.githubusercontent.com/apache/superset/master/superset/config.py); its bypass is
CVE-2025-55674). ClickHouse enforces server-side (`readonly=1`,
[docs](https://clickhouse.com/docs/operations/settings/permissions-for-queries)). sqlglot exposes 568 typed `exp.Func`
classes and `exp.Anonymous` for unknown names; key the list on the class for typed nodes and the lowercased name
for Anonymous. Two traps: typed nodes can be dangerous (`NextValueFor`, `Uuid`, `Rand`), and sqlglot builds nodes the
user didn't write (`DATE_FORMAT` → `TimeToStr` + `TsOrDsToTimestamp`, `STRING_AGG` → `GroupConcat`), so build the
list from what a per-dialect corpus parses to. Families: SQL:2016 aggregates, math, string, date, conditional,
window, cast; references: [PG](https://www.postgresql.org/docs/current/functions.html),
[MySQL](https://dev.mysql.com/doc/refman/8.4/en/built-in-function-reference.html),
[MariaDB](https://mariadb.com/kb/en/built-in-functions/), [T-SQL](https://learn.microsoft.com/en-us/sql/t-sql/functions/functions),
[SQLite](https://www.sqlite.org/lang_corefunc.html).

any `sig=`/`token=`/`X-Amz-*`, and every path id. A non-public link often answers **200 `text/html`**: judge by the
bytes (xlsx `PK\x03\x04`, or text) and the type, never the status.

## 7. SSRF guard for the downloader

OWASP ([cheat sheet](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)):
http(s) only, validate every resolved record, connect to the validated address (a second lookup is a bypass), no
automatic redirects, normalize IPv4-mapped and NAT64 first.

Python `ipaddress` on 3.11.14 (verified): `64:ff9b::a9fe:a9fe` (NAT64 → the metadata address) and `::127.0.0.1`
report **`is_global=True`**; `100.64.0.1` (CGNAT) is not private but not global. Unwrap first, then accept only
`is_global` for a URL fetch. Encoded IPs (`2130706433`, `0x7f.1`, `127.1`) resolve to 127.0.0.1: check resolved
addresses, not the string. httpx defaults: `trust_env=True` (proxies route around a check), automatic decoding of
gzip/zstd (a bomb past any cap): set `trust_env=False`, `Accept-Encoding: identity`, count bytes while streaming.
httpx 0.28's transport has no `network_backend`; httpcore's pool does, and `connect_tcp` is the one place every
connection passes. safehttpx (gaps: DNS-over-HTTPS fallback, no `is_global`, no redirects) and advocate (dead since
2020) aren't worth depending on.

## 8. xlsx bombs

openpyxl doesn't guard XML bombs without defusedxml ([docs](https://openpyxl.readthedocs.io/en/stable/)); expat ≥ 2.4
refuses billion laughs. `zipfile` never unpacks past a part's declared size (CPython `zipfile.py`), so the central
directory's sizes are a real bound: check entries, total declared size and names before `read_excel`.

## 9. MySQL / MariaDB TLS with a pinned IP

PyMySQL takes an `SSLContext` (`ssl=`), wraps with `server_hostname=self.host`, and `connect(sock=…)` takes a
pre-connected socket with `defer_connect=True`: connect to the checked address, verify the name. PlanetScale: system
roots ([docs](https://planetscale.com/docs/vitess/connecting/secure-connections)). AWS RDS: private CAs, clients need
`global-bundle.pem` ([RDS SSL](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/UsingWithRDS.SSL.html)). Never
a CA path from the user's string (ADR-0010).

## Addendum (from the build, 2026-11-20)

What the build found on the real engines and the live check, and where it departed from the recommendations:
- **Driver: pyodbc + msodbcsql18** (the user's choice). The "needs a -155 converter" con doesn't hold: SQLAlchemy's
  pyodbc dialect registers the DATETIMEOFFSET converter on connect (`sqlalchemy/dialects/mssql/pyodbc.py:731`); the
  own-types test reads DATETIMEOFFSET as an instant. `HostNameInCertificate` keeps TLS on the name under the pin.
  On Debian 13 the Microsoft repo needs its `packages-microsoft-prod.deb` (the 2025 signing key); on macOS the
  driver dlopens OpenSSL 3 from `/opt/homebrew/opt/openssl`, which now points at OpenSSL 4 (`DYLD_LIBRARY_PATH`).
- **The can-write check** runs at database and schema level (`fn_my_permissions(NULL, 'DATABASE')` plus
  `sys.database_permissions` grants to the login or its roles), not a `sys.objects` scan per connection.
- **MariaDB 11.4.13 verified**: 1792 on every write, `SLEEP` cut by `max_statement_time` with **1969**, 1193 on
  `max_execution_time`, TINYINT(1) and DATE cursor types as MySQL's, TLS on by default (self-signed).
- **SQL Server returns a keyless table in another order under load** (a parallel scan; its heap reuses freed pages
  after a replace): the contract's samples read order (recurrence of P58-03). The load is a serial scan
  (`OPTION (MAXDOP 1)`) and the source oracle compares values against the CSV's rows in the source's order.
- **T-SQL CTEs are always recursive** (no RECURSIVE keyword): the table rule reads them so on T-SQL only; on Postgres a
  CTE's own name in its body is still the real table.
- **APPLY, `#temp`, `##temp` and schema-qualified functions** passed the 5.8a table rule: walked now.
- **Google Sheets: a sheet made from an uploaded file has a random first `gid`** and `export?gid=0` answers **400**
  (the live check); a link with no `gid` exports the first tab without one.
- **Sheets export kept as CSV**, not xlsx as recommended: it is what the Sheets source already reads, and the live
  check read the downloaded CSV exactly as the original.
- **No per-provider host allowlist on redirects**: every hop is held to the public internet instead (any https
  CSV/xlsx URL is in scope, and providers move their download hosts).
- **defusedxml not added**: expat refuses billion laughs; openpyxl's lxml path doesn't resolve entities. The real
  bound is size (declared ≤ 150 MB, ≤ 10,000 parts) and a CSV header's width as the reader takes it.
- **OneDrive/SharePoint stay UNVERIFIED live**: mocked chains only, and the README says so.
- **Azure SQL** routes on the server name; an IP pin there is untested, so only self-hosted and RDS SQL Server are claimed.
